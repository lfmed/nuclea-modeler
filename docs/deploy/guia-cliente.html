Pré-requisitos

RecursoMínimoOnde obter
Workspace Databricks Qualquer tier com Unity Catalog ativado Já provisionado
SQL Warehouse Serverless ou Pro, 2X-Small basta SQL → SQL Warehouses → Create
Unity Catalog 1 catalog + USAGE pro SP do app Catalog Explorer
Permissões do deployer Workspace Admin ou CAN_MANAGE em apps + CREATE SCHEMA no catalog Acordar com admin
Databricks CLI ≥ 0.250.0 autenticado pip install databricks-cli
Lakebase Postgres (opcional) Apenas se for usar engenharia reversa contra Lakebase Compute → Lakebase → Create
💡 Não precisa Node/Python local. O build da UI (Vite) e a instalação de deps Python (uv) rolam dentro do container do Databricks Apps automaticamente.
1

Clone do repositório

O código-fonte é versionado no Git. Faça clone num diretório local:

git clone https://github.com/lfmed/nuclea-modeler.git
cd nuclea-modeler
📦 Se você não tiver acesso público ao repositório A Núclea irá compartilhar com você via convite no GitHub ou ZIP do release.
2

Parametrize app.yml

O arquivo app.yml.example é o template. Copie e edite:

cp app.yml.example app.yml

Placeholders para substituir

Procure por [ALTERAR] no arquivo:

PlaceholderO que éOnde achar
<WAREHOUSE_ID> ID do SQL Warehouse Final da URL ao abrir o warehouse:
/sql/warehouses/<ID>
<CATALOG_NAME> Unity Catalog onde o app guarda estado Catalog Explorer
<LAKEBASE_INSTANCE_NAME> (opcional) Nome da instance Lakebase Compute → Lakebase
⚠️ Se você NÃO vai usar Lakebase Remova ou comente todo o bloco nuclea-lakebase em resources:. O resto do app funciona normalmente.

Schema

O NUCLEA_SCHEMA (default: nuclea_modeler) é criado automaticamente na primeira execução pelas migrations — você não precisa criar manualmente.

3

Crie o secret scope (opcional)

Necessário apenas se for cadastrar conexões ODBC/REST a sistemas legados que exigem credenciais.

databricks secrets create-scope nuclea-modeler --profile <SEU_PROFILE>

Se mudou NUCLEA_SECRETS_SCOPE no app.yml, use o mesmo nome aqui.

4

Crie o app no Databricks

Provisiona o service principal do app + assinatura computacional:

databricks apps create nuclea-modeler --profile <SEU_PROFILE>
✅ Anote o Application ID do SP retornado Você vai precisar dele no próximo passo pra dar permissões no catalog.
5

Permissões no Unity Catalog

O service principal do app precisa de pelo menos:

-- Substitua <CATALOG_NAME> e <SP_APPLICATION_ID>

GRANT USAGE ON CATALOG <CATALOG_NAME> TO `<SP_APPLICATION_ID>`;
GRANT CREATE SCHEMA ON CATALOG <CATALOG_NAME> TO `<SP_APPLICATION_ID>`;

-- Após primeira run, o schema existe — concede tudo dentro dele:
GRANT ALL PRIVILEGES
  ON SCHEMA <CATALOG_NAME>.nuclea_modeler
  TO `<SP_APPLICATION_ID>`;
💡 Execute no SQL Editor Use o mesmo SQL Warehouse declarado no app.yml.
6

Deploy do código

Sincroniza o repositório pro workspace e dispara o build:

6.1 — Sincronizar

databricks sync . \
  /Workspace/Users/<seu-usuario>/nuclea-modeler \
  --profile <SEU_PROFILE> --full

6.2 — Deploy

databricks apps deploy nuclea-modeler \
  --source-code-path /Workspace/Users/<seu-usuario>/nuclea-modeler \
  --profile <SEU_PROFILE>

Demora ~1 min. O pipeline interno faz: instalar deps Python (uv), npm install, vite build, rodar migrations SQL, subir uvicorn.

6.3 — Acompanhar os logs

databricks apps logs nuclea-modeler --profile <SEU_PROFILE>
✅ Procure por esta linha:
[migrations] summary: {'applied': N, 'skipped': 0, 'drifted': 0, 'failed': 0}
Se applied = N (≥ 1) e failed = 0, está tudo certo.
7

Acessar o app

Pegue a URL pelo CLI:

databricks apps get nuclea-modeler --profile <SEU_PROFILE> --output json | grep '"url"'

O endereço fica assim:

https://nuclea-modeler-<WORKSPACE_ID>.cloud.databricksapps.com
🔐 SSO obrigatório Todos os endpoints exigem login via SSO do workspace — incluindo /livez, /readyz. Para monitoramento externo, vide docs/operations/deploy-runbook.md.

Primeiro usuário

O primeiro acesso pode precisar receber a role ADMIN manualmente. Faça via SQL:

INSERT INTO <CATALOG>.<SCHEMA>.user_roles
  (user_role_id, user_email, role_name, granted_at, granted_by, is_active)
VALUES (uuid(), 'seu-email@empresa.com', 'ADMIN', now(), 'system', true);
★

Bonus — Genie + Dashboard externos

Depois do app rodando, recursos opcionais que enriquecem a análise:

  • Lakeview Dashboard: KPIs em tempo real sobre os modelos. Spec em databricks/dashboards/nuclea_modeler_dashboard.json. Substitua stable_classic_pg4xe1_catalog.data_catalog_app pelo seu <CATALOG>.<SCHEMA> antes de subir via databricks lakeview create.
  • Genie Space: perguntas em linguagem natural sobre o catálogo. Setup em databricks/dashboards/GENIE_SETUP.md.

🔧 Troubleshooting

SintomaCausaFix
[migrations] FAILED ... SCHEMA_NOT_FOUND SP do app sem CREATE SCHEMA no catalog Voltar ao passo 5
Provided OAuth token does not have required scopes: postgres Resource nuclea-lakebase não declarado no app.yml Adicione o bloco em resources: e re-deploy
[migrations] DRIFT detected Mesmo arquivo SQL com hash diferente do registrado Normal após upgrade. App continua rodando — revise a migration manualmente
DER ou Dashboard vazio depois do deploy Schema criado mas seeds não rodaram databricks apps logs e veja erros nas migrations 003/004/009
401 em todos os endpoints SSO força auth e cookie do browser não está sincronizado Abrir no mesmo workspace logado e tentar de novo

🔄 Atualizações

Quando a Núclea publicar uma nova versão:

git pull origin main

databricks sync . \
  /Workspace/Users/<seu-usuario>/nuclea-modeler \
  --profile <SEU_PROFILE>

databricks apps deploy nuclea-modeler \
  --source-code-path /Workspace/Users/<seu-usuario>/nuclea-modeler \
  --profile <SEU_PROFILE>
🧬 Migrations automáticas Novas migrations são aplicadas no startup (rastreadas por checksum em schema_migrations). Não duplica em re-deploys.

💾 Estado armazenado

Todo o estado vai pro Unity Catalog em <CATALOG>.<SCHEMA> — 18+ tabelas Delta:

  • systems, entities, attributes, relationships
  • reconciliation_tickets, extractions
  • audit_log (trilha imutável)
  • glossary_terms, flags, lakebase_sandboxes
  • e mais…
🛡️ Nenhum banco externo Não há Postgres, Redis ou outro store. Backup = DEEP CLONE ou CREATE BACKUP do schema.
